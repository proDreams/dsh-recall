# dsh-recall

**Русский** · [English](./README.md)

Плагин возврата контекста для **DeepSeek Harness** (`dsh`). Крупный результат инструмента держит
в разговоре первые 600 символов; остальное уходит на диск под коротким id объекта, и модель может
достать любой срез через `recall("<id>")`. Полоса под композером показывает три цифры, по которым
видно, окупается ли обмен: сколько вынесено, сколько токенов это сэкономило и как часто модель
реально возвращалась за остатком.

## Зачем

Замер по 8 504 результатам инструментов из реальных сессий:

| факт | значение |
|---|---|
| результатов крупнее 6 КБ | 4.6% от всех результатов |
| …их доля во всём объёме tool-результатов | 40.7% |
| …из них не открываются повторно | 76% |

То есть дорогая часть сессии — это несколько огромных результатов, которые никто не читает дважды.
Вынос убирает токены, которые иначе **пересылались бы на каждом следующем шаге**: экономия равна
`removed_tokens × remaining_steps × cache_price`, а не просто `removed_tokens`.

Потолок честно: tool-результаты — примерно 46% контекста, так что вынос *всех* результатов всё
равно упирается в ~18% контекста. На маршруте, где чтение кэша billed почти как input, это реальные
20–25% длинной сессии; на first-party маршруте с дешёвым кэшем — единицы процентов, и там рычаг
это свежий input и число шагов.

## Что именно делает

- Хук `tools/post-execute`, смотрит на поверхность сессии.
- Трогает только результаты **старше двух последних** (`KEEP = 2`) и **длиннее 2 500 символов**
  (`THRESHOLD`).
- Заменяет результат на `голова (600 символов) + заметка [recall]` тем же replay-safe приёмом, что
  и штатный pruner: событие `compaction/prune` (оно оценивает и цитирует затенённый узел), затем
  событие `tool/result` с `surfaceOp: {op:'replace'}`. В durable-логе оригинал остаётся.
- Полный текст пишет в `~/.local/share/dsh-recall/objects/<id>.txt`, в `index.jsonl` добавляет
  строку.
- Регистрирует инструмент `recall`: `recall(id)`, `recall(id, start, count)`; срез по умолчанию
  8 000 символов, жёсткий предел 24 000, чтобы recall не раздувал обратно тот контекст, ради
  которого его и выносили. Id проверяется (`/^[0-9a-f]{6,32}$/i`) до обращения к файловой системе —
  модель придумывает id.
- Идемпотентен: результат, который уже содержит маркер `[recall]`, пропускается, поэтому рестарты и
  повторные проходы не наслаивают указатели.

## Пилюля

Компактная пилюля в `shell.overlay`, которая встаёт ровно над бейджем **dsh-tidewatch**, если тот
установлен: она раз в 500 мс читает прямоугольник чипа тайдвоча и выравнивается по нему, так что
два элемента читаются как одна карточка. Без тайдвоча — падает в правый нижний угол. Общего с
тайдвочем ничего, кроме имени CSS-класса, поэтому плагины остаются независимыми пакетами со своими
релизами. Текст следует языку интерфейса (en/ru). По клику раскрываются последние 12 выносов с
именем инструмента, размером и возрастом. Данные берёт из `GET /recall/api/stats` на loopback-порту
хоста, опрос раз в 12 с:

```json
{"offloaded":196,"charsSaved":1207034,"tokensSaved":301759,"recalls":0,"threshold":2500,"recent":[…]}
```

`offloaded` и `charsSaved` пересчитываются из `index.jsonl`, поэтому переживают рестарт; `recalls` —
единственный счётчик, который живёт в памяти и зеркалится в `counters.json`.

## Установка

Профиль web / tui:

```sh
dsh plugin --profile web add github:sh-222/dsh-recall
```

Профилем **desktop** (Electron) CLI не управляет — так задумано. Добавь зависимость и строку в
bundles в `~/.dsh/profiles/desktop/package.json`, затем поставь:

```json
{
  "dependencies": { "dsh-recall": "github:sh-222/dsh-recall" },
  "dsh": { "profile": { "bundles": ["…", "dsh-recall"] } }
}
```

```sh
cd ~/.dsh/profiles/desktop && pnpm install --ignore-scripts
```

После этого — перезапуск харнесса. Плагин загружается только на старте.

### Установка из локального чекаута

`dsh plugin --profile <p> add ~/Projects/dsh-recall` пишет зависимость `link:`, а node в этом
случае ищет `@deepseek-ai/*` по реальному пути, а не через профиль — без симлинков плагин падает с
`ERR_MODULE_NOT_FOUND`:

```sh
cd ~/Projects/dsh-recall && mkdir -p node_modules/@deepseek-ai
ln -sfn /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-llm   node_modules/@deepseek-ai/
ln -sfn /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-tools node_modules/@deepseek-ai/
```

## Настройка порогов

`THRESHOLD` и `HEAD` — константы в начале `index.js`. Выбраны по распределению размеров из 12
реальных сессий (1 150 результатов, 487 тыс. токенов), а не на глаз:

| порог | голова | результатов задето | сэкономлено | доля объёма | объектов на recall |
|---|---|---|---|---|---|
| 6 000 | 1 200 | 40 | 114 тыс. ток | 23.5% | 40 |
| 4 000 | 600 | 103 | 186 тыс. ток | 38.1% | 103 |
| **2 500** | **600** | 218 | 258 тыс. ток | **53.0%** | 218 |
| 1 500 | 600 | 368 | 308 тыс. ток | 63.3% | 368 |

2 500 / 600 — это колено: покрытие удваивается по сравнению с 6 000, а число объектов остаётся
около 18 на сессию. Переход на 1 500 даёт десять пунктов объёма за тройное число объектов — больше
шансов, что модель погонится за указателем там, где перечитать было бы дешевле. Голову ниже
нескольких сотен символов не опускать: модель должна видеть форму результата.

Как читать полосу: отношение `recalls / offloaded` — это и есть эксперимент. Около нуля — содержимое
не понадобилось. Близко к единице — голова мала, поднимай `HEAD` примерно до 2 000, прежде чем
трогать остальное.

## Хранение

```
~/.local/share/dsh-recall/objects/<id>.txt   полный текст, один файл на вынесенный результат
~/.local/share/dsh-recall/index.jsonl        {session, seq, tool, id, chars, ts} на каждый вынос
~/.local/share/dsh-recall/counters.json      {hits, charsSaved, recalls}
```

Один плоский пул на `$HOME`, общий для всех проектов; сессия-владелец записана в индексе. Id =
`md5(sessionId:seq:length)`, поэтому одинаковые по размеру результаты из разных сессий не
сталкиваются. Измеренная цена: ~8 КБ на объект, 1,3 МБ на сессию с 196 выносами.

**Ротации нет.** Объекты не удаляются никогда. При 8 КБ на объект это ~120 МБ на 10 000 выносов —
на фоне самих логов сессий незаметно, но если нужен потолок, удаляй `objects/*` старше N дней и
пересобирай `index.jsonl` из оставшегося.

## Честные ограничения

- Указатель полезен, пока голова объясняет, что это был за результат. Поэтому в заметке есть имя
  инструмента и полный размер.
- Сессии, возобновлённые из прошлого процесса, стартуют с пустой картой `callId → имя инструмента`,
  поэтому старый результат, вынесенный сразу после рестарта, может быть подписан `tool` вместо
  `read`. Косметика.
- `counters.json` пишут все рантаймы, которые монтируют плагин (host и web). Побеждает последний
  записавший, так что `recalls` может быть затёрт вторым экземпляром; остальные цифры полосы
  пересчитываются из индекса и остаются верными.

## Тест

```sh
npm run check
HOME=$(mktemp -d) node test/reaper.mjs   # HOME переопределён, реальный каталог состояния не трогаем
```

Тест прогоняет хук на самодельной сессии: проверяет, что заменяется только старый и крупный
результат, что указатель несёт настоящее имя инструмента из парного `tool/call`, что свежий крупный
результат не тронут, и что `recall` отдаёт запрошенный срез и увеличивает счётчики.
