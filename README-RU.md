# dsh-recall

**Русский** · [English](./README.md)

Плагин возврата контекста для **DeepSeek Harness** (`dsh`). Крупный результат инструмента держит
в разговоре первые 600 символов; остальное уходит на диск под коротким id объекта, и модель может
достать любой срез через `recall("<id>")`. Полоса под композером показывает три цифры, по которым
видно, окупается ли обмен: сколько вынесено, сколько токенов это сэкономило и как часто модель
реально возвращалась за остатком.

## Зачем

Замер по 8 504 результатам инструментов из реальных сессий:

| факт | значение |
|---|---|
| результатов крупнее 6 КБ | 4.6% от всех результатов |
| …их доля во всём объёме tool-результатов | 40.7% |
| …из них не открываются повторно | 76% |

То есть дорогая часть сессии — это несколько огромных результатов, которые никто не читает дважды.
Вынос убирает токены, которые иначе **пересылались бы на каждом следующем шаге**: экономия равна
`removed_tokens × remaining_steps × cache_price`, а не просто `removed_tokens`.

Потолок честно: tool-результаты — примерно 46% контекста, так что вынос *всех* результатов всё
равно упирается в ~18% контекста. На маршруте, где чтение кэша billed почти как input, это реальные
20–25% длинной сессии; на first-party маршруте с дешёвым кэшем — единицы процентов, и там рычаг
это свежий input и число шагов.

## Что именно делает

- Хук `tools/post-execute`, смотрит на поверхность сессии.
- Трогает только результаты **старше двух последних** (`keep: 2`) и **длиннее 2 500 символов**
  (`thresholdChars: 2500`).
- Заменяет результат на `голова (600) + заметка [recall] + хвост (240)` тем же replay-safe приёмом,
  что и штатный pruner: событие `compaction/prune` (оно оценивает и цитирует затенённый узел), затем
  событие `tool/result` с `surfaceOp: {op:'replace'}`. В durable-логе оригинал остаётся. Сокращается
  только текст: нетекстовые блоки (картинки) переезжают без потерь.
- Полный текст пишет в локальную SQLite-базу `~/.local/share/dsh-recall/store.db` — со сжатием и
  дедупликацией по SHA-256, так что одинаковый вывод хранится один раз.
- Пропускает результат, если указатель не короче оригинала.
- Регистрирует инструмент `recall`: `recall(id)`, `recall(id, start, count)`; срез по умолчанию
  8 000 символов, жёсткий предел 24 000, чтобы recall не раздувал обратно тот контекст, ради
  которого его и выносили. Id проверяется (`/^[0-9a-f]{6,32}$/i`) до обращения к файловой системе —
  модель придумывает id.
- Идемпотентен структурно, а не по тексту: база помнит, какие пары `(session, seq)` уже вынесены (а
  замена ссылается на оригинал через `sourceEventSeqs`), поэтому инструмент, который просто
  *напечатал* маркер `[recall]`, не заставит сборщик пропустить настоящий результат.

## Чего плагин не делает: сжатие на 15%

`dsh-recall` не решает, *когда* сжимать контекст, и не трогает размер окна модели. Процентное сжатие —
это штатный плагин `@deepseek-ai/dsh-compaction-basic`, и настраивается он в собственном патч-слое
профиля (`~/.dsh/profiles/<profile>/cordis.patch.yml`):

```yaml
- id: compaction-basic
  name: "@deepseek-ai/dsh-compaction-basic"
  config:
    thresholdRatio: 0.15
    retainRatio: 0.05
```

`thresholdRatio` — доля окна модели, при которой запускается проход сжатия; `retainRatio` — доля,
которая остаётся после него. Штатные значения — `0.8` / `0.16`. На этой машине в десктопном профиле
стоит `0.15 / 0.05`, то есть окно 256k сжимается уже на ~38k токенов и сохраняет ~13k — рабочее окно
получается заметно меньше возможностей модели. Это и есть ручка, которую надо поднимать, если нужно
больше места:

```yaml
thresholdRatio: 0.6   # сжимать на 60% окна вместо 15%
retainRatio: 0.15
```

Механизмы независимы и дополняют друг друга: компакция переписывает *всю* историю в сводку, когда окно
заполняется, а `dsh-recall` историю не трогает — он укорачивает отдельные крупные результаты
инструментов, и именно это откладывает момент, когда компакция вынуждена сработать. Выключить recall —
на 15% не влияет; поднять 15% — на работу recall не влияет.

## Пилюля

Компактная пилюля в `shell.overlay`, которая встаёт ровно над бейджем **dsh-tidewatch**, если тот
установлен: она раз в 500 мс читает прямоугольник чипа тайдвоча и выравнивается по нему, так что
два элемента читаются как одна карточка. Без тайдвоча — падает в правый нижний угол. Общего с
тайдвочем ничего, кроме имени CSS-класса, поэтому плагины остаются независимыми пакетами со своими
релизами. Текст следует языку интерфейса (en/ru). По клику раскрываются последние 12 выносов с
именем инструмента, размером и возрастом. Данные берёт из `GET /recall/api/stats` на loopback-порту
хоста, опрос раз в 12 с:

```json
{"offloaded":196,"charsSaved":1207034,"tokensSaved":301759,"recalls":0,"threshold":2500,"recent":[…]}
```

`offloaded` и `charsSaved` пересчитываются из `index.jsonl`, поэтому переживают рестарт; `recalls` —
единственный счётчик, который живёт в памяти и зеркалится в `counters.json`.

## Установка

Профиль web / tui:

```sh
dsh plugin --profile web add github:sh-222/dsh-recall
```

Профилем **desktop** (Electron) CLI не управляет — так задумано. Добавь зависимость и строку в
bundles в `~/.dsh/profiles/desktop/package.json`, затем поставь:

```json
{
  "dependencies": { "dsh-recall": "github:sh-222/dsh-recall" },
  "dsh": { "profile": { "bundles": ["…", "dsh-recall"] } }
}
```

```sh
cd ~/.dsh/profiles/desktop && pnpm install --ignore-scripts
```

После этого — перезапуск харнесса. Плагин загружается только на старте.

### Установка из локального чекаута

`dsh plugin --profile <p> add ~/Projects/dsh-recall` пишет зависимость `link:`, а node в этом
случае ищет `@deepseek-ai/*` по реальному пути, а не через профиль — без симлинков плагин падает с
`ERR_MODULE_NOT_FOUND`:

```sh
cd ~/Projects/dsh-recall && mkdir -p node_modules/@deepseek-ai
ln -sfn /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-llm   node_modules/@deepseek-ai/
ln -sfn /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-tools node_modules/@deepseek-ai/
```

## Настройка порогов

Пороги — это конфиг плагина, а не константы в исходнике, поэтому задаются в патче профиля:

```yaml
- id: dsh-recall
  name: dsh-recall
  config:
    thresholdChars: 2500   # выносим только то, что длиннее
    headChars: 600         # остаётся в контексте в начале
    tailChars: 240         # остаётся в конце (там инструменты держат свои подсказки)
    keep: 2                # последние результаты не трогаем
    enabled: true          # выключить сборщик, оставив recall(id)
```

`thresholdChars: 2500 / headChars: 600` выбраны по распределению размеров из 12 реальных сессий
(1 150 результатов, 487 тыс. токенов), а не на глаз:

| порог | голова | результатов задето | сэкономлено | доля объёма | объектов на recall |
|---|---|---|---|---|---|
| 6 000 | 1 200 | 40 | 114 тыс. ток | 23.5% | 40 |
| 4 000 | 600 | 103 | 186 тыс. ток | 38.1% | 103 |
| **2 500** | **600** | 218 | 258 тыс. ток | **53.0%** | 218 |
| 1 500 | 600 | 368 | 308 тыс. ток | 63.3% | 368 |

2 500 / 600 — это колено: покрытие удваивается по сравнению с 6 000, а число объектов остаётся
около 18 на сессию. Переход на 1 500 даёт десять пунктов объёма за тройное число объектов — больше
шансов, что модель погонится за указателем там, где перечитать было бы дешевле. Голову ниже
нескольких сотен символов не опускать: модель должна видеть форму результата.

Как читать полосу: отношение `recalls / offloaded` — это и есть эксперимент. Около нуля — содержимое
не понадобилось. Близко к единице — голова мала, поднимай `HEAD` примерно до 2 000, прежде чем
трогать остальное.

## Хранение

```
~/.local/share/dsh-recall/store.db   одна база SQLite (WAL)
```

Три таблицы: `objects` (id, session, seq, tool, учёт символов и токенов, время), `blobs` (полезная
нагрузка, deflate, ключ — SHA-256 исходного текста) и `counters` (только `recalls`, всё остальное —
агрегат). База вместо каталога файлов даёт четыре вещи: одинаковый вывод хранится один раз,
нагрузка сжимается, цифры полосы — это один запрос вместо полного разбора `index.jsonl`, и два
процесса могут писать параллельно без «побеждает последний».

Один плоский пул на `$HOME`, общий для всех проектов. Id = `md5(sessionId:seq:length)`. Смотреть
можно любым SQLite-клиентом:

```sh
sqlite3 ~/.local/share/dsh-recall/store.db 'select tool, chars, datetime(ts/1000,"unixepoch") from objects order by ts desc limit 5'
```

Старая раскладка 0.3 (`objects/*.txt` + `index.jsonl`) импортируется при первом запуске, а JSONL
переименовывается в `index.jsonl.migrated`; старые id продолжают открываться. `node:sqlite` —
модуль стандартной библиотеки, зависимостей не добавляет, но требует Node >= 22.5. На более старом
Node плагин пишет одну строку в лог и грузится без хранилища: выноса нет, `recall` сообщает о
недоступности — вместо того чтобы уронить профиль.

**Ротации нет.** Объекты не удаляются никогда. Нагрузка сжата, но если нужен потолок:
`delete from objects where ts < …`, затем `delete from blobs where hash not in (select hash from
objects)`.

## Честные ограничения

- Указатель полезен, пока голова объясняет, что это был за результат. Поэтому в заметке есть имя
  инструмента и полный размер.
- Сессии, возобновлённые из прошлого процесса, стартуют с пустой картой `callId → имя инструмента`,
  поэтому старый результат, вынесенный сразу после рестарта, может быть подписан `tool` вместо
  `read`. Косметика.
- Два экземпляра харнесса делят один пул; SQLite сериализует записи (`busy_timeout`), а все цифры
  полосы, кроме `recalls`, вычисляются из таблиц, поэтому разойтись не могут.
- Сборщик срабатывает до того, как текущий результат попадает на поверхность, поэтому работает по
  более ранним результатам: последний крупный результат сессии остаётся целым, пока не появится
  что-то новее.

## Тест

```sh
npm run check   # node --check по всем трём исходникам
npm test        # хранилище, сборщик, интеграция с настоящей Session, HTTP, монтирование клиента
```

Пять проб, каждая подменяет `HOME` на временный каталог, чтобы не трогать настоящий:

- `test/store.mjs` — точный roundtrip, учёт code points, дедупликация по хешу, сжатие, агрегаты,
  защита от чужой базы и миграция раскладки 0.3;
- `test/reaper.mjs` — заменяется только старый крупный результат, указатель несёт голову, хвост и
  настоящее имя инструмента, свежий крупный результат не тронут, `recall` отдаёт срез, а второй
  проход ничего не выносит;
- `test/realsession.mjs` — та же замена через **настоящий** `Session` из `@deepseek-ai/dsh-session`,
  то есть контракт замены поверхности проверяет сам харнесс, а не заглушка;
- `test/http-harness.mjs` — `GET /recall/api/stats` и его 404;
- `test/client-harness.mjs` — клиентская половина монтируется и регистрирует свою запись в
  `shell.overlay`.
